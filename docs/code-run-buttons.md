# Run buttons beside code

The lane next to line numbers offers a menu for runnable code. Tests keep their existing pass/fail buttons and coverage actions. A default file run command is available at the beginning of executable files; C/C++ uses the `main` declaration when present. Make targets, npm scripts and fixed module tasks have buttons at their declarations. Several actions on one line share a button and a scrollable menu.

Python, JavaScript and Docker modules supply optional `code_actions` metadata. Rules describe the language, declaration pattern, command and optional Windows override. The named `symbol` capture fills `{symbol}`; names are validated before forming a command. An optional `context` pattern limits actions to a region, and `direct_children` selects their first indentation level, so Compose buttons apply to services and not similarly indented volumes or networks. Highlighted comments and strings are excluded. Custom modules can add rules without changing the IDE.

Current function actions support top-level Python functions declared with empty parameter lists (sync/async), exported JavaScript functions/arrows with empty parameter lists, and explicit CommonJS export assignments. Functions requiring arguments do not receive direct-call actions. A file is loaded before its function runs, so its top-level statements run normally. Python imports use a persistent module entry and preserve sibling imports; its `__main__` guard is not triggered and the function launcher suppresses bytecode cache files. JavaScript uses Node's module loader and file URLs. See the [Python import machinery](https://docs.python.org/3.12/library/importlib.html#importing-a-source-file-directly) and [Node ESM/CommonJS interoperability](https://nodejs.org/api/esm.html#interoperability-with-commonjs).

Common Lisp uses its reader, rather than a regexp, to find unquoted top-level `defun` forms with empty lambda lists, tracking `in-package`. A new SBCL process loads the project's selected ASDF system (or the first non-test system if present), loads the file and calls the function in its package. Its result and output go to a separate Run tab; Stop and Rerun work there. Loading a file/system can execute its top-level forms. Other Lisp dialects retain their file actions.

Docker adds named stage builds and Compose service build/start/stop/log actions. Nothing is run by recognizing a declaration: choose an action in its menu. Before executing a function, the IDE saves changed files and rechecks that the declaration and enabled module still exist. Cached buttons are invalidated after edits or module changes.

The optional manifest field is ignored by older IDEs. Updated modules retain their previous file, check and test commands; this was checked with the actual published Light 1.3.0 executable before release.
